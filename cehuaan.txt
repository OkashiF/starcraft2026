
星际RTS页游设计方案——**《星渊黎明》(Dawn of the Abyss)**。

---

## 1. 游戏概述与核心循环

* **游戏名称：** 《星渊黎明》(Dawn of the Abyss)
* **游戏类型：** 2D俯视角 科幻即时战略（RTS）网页游戏
* **开发引擎：** Phaser 3 + EasyStar.js (寻路引擎) + Socket.io (若含联机功能)
* **核心循环：** 收集资源 -> 建设基地与科研 -> 组建舰队/军队 -> 夺取战略节点（战斗） -> 推进剧情与解锁永久科技。

---

## 2. 背景剧情与阵营设定

为了让战斗有代入感，游戏采用“**流浪与复国**”的叙事主线。

* **背景故事：** 人类“太阳帝国”遭遇未知硅基生物“噬星者”的突袭，母星沦陷。玩家扮演“远征军第7舰队”的指挥官，带领最后一艘超级母舰（方舟）逃至未知的“星渊星区”。你需要在这里建立前哨站，收集资源，寻找失散的舰队，并最终反攻母星。
* **战役模式（剧情表现）：** 每场对战不仅是一张地图，而是星区的一颗行星。过场采用视觉小说（Visual Novel）形式的立绘对话；战斗中途会有突发剧情（如：“指挥官，探测到地下有高能反应，虫群正在涌出，请立即改变防线！”），增加沉浸感。

---

## 3. “有意义的战斗”系统设计

传统RTS容易陷入“憋一波大军F2A（全军突击）”的无聊循环。为了让战斗变得有意义，我们引入以下机制：

1. **单位老兵制与“折跃撤离”：**
* 每个单位击杀敌人后会获得经验值，晋升为“老兵”甚至“英雄”（获得血量上限、射程或特殊技能提升）。
* **核心机制：** 战役结束后，存活的高星级单位可以被“提取”回母舰。在下一场战役中，你可以花费额外资源将这些“身经百战的老兵”直接空投到战场。**这让玩家会像爱护RPG角色一样爱护自己的高阶兵种，避免无意义的送死。**


2. **战利品与永久科技：**
* 地图上存在特殊的“外星遗物”或“精英中立怪物”。
* 通过战斗夺取这些目标，不仅能获得局内资源，还能掉落“科技核心”。战局结束后，这些核心用于在主菜单的“方舟母舰”中解锁全局被动天赋（如：机甲移动速度永久+5%）。


3. **地缘战略节点控制：**
* 地图不只是平地。设计“雷达站”（占领后开战局全图迷雾）、“轨道炮台”（占领后可定期呼叫地图打击）、“热能泉”（占领后加快全军回血）。**迫使玩家为了争夺节点而在前期就展开激烈的小规模交火。**



---

## 4. 基地运营要素

运营是战斗的基石，采用“双资源+电力”系统限制无限暴兵：

* **晶矿（基础资源）：** 分布在地图表面，通过建造“采矿无人机”收集，用于建造基础建筑和步兵。
* **瓦斯（高级资源）：** 位于特定的地热泉眼，需要建造“瓦斯精炼厂”，用于生产机甲、星舰和高级科技。
* **电力系统（运营限制）：** 所有的兵营、科研所、防空塔都需要消耗电力。玩家必须规划“核能发电站”的位置，一旦发电站被摧毁，基地防卫武器将全部瘫痪（给玩家突袭敌方能源基地的战术选择）。

---

## 5. 丰富的兵种设计 (以人类远征军为例)

兵种设计遵循 **“石头-剪刀-布”** 的克制原则（轻甲-重甲-护盾），并分为三大核心体系：

| 兵种类别 | 单位名称 | 定位与特色技能 | 战术克制 |
| --- | --- | --- | --- |
| **步兵系** | 陆战队员 (Marine) | **炮灰/核心输出：** 成本极低，可升级“兴奋剂”（消耗血量提升射速）。 | 克制轻甲，被范围伤害克制 |
| **步兵系** | 火蝠突击队 (Firebat) | **近战AOE：** 喷火器造成锥形范围伤害。 | 克制海量虫群/轻甲步兵 |
| **步兵系** | 幽灵特工 (Ghost) | **隐形/狙击：** 可隐身潜入敌后，使用EMP瘫痪敌方建筑或机甲。 | 战术干扰，克制重型单位 |
| **机甲系** | 战狼轻装车 (Hellion) | **高机动侦察：** 移动速度极快，用于前期抢占战略节点。 | 克制落单步兵 |
| **机甲系** | 攻城机甲 (Siege Walker) | **阵地战王者：** 两种形态。移动形态火力弱；架设后变为超远距离火炮，但无法移动。 | 克制建筑与密集集群 |
| **星舰系** | 怨灵战机 (Wraith) | **制空权争夺：** 对空特化的战机，可升级对地导弹。 | 克制敌方空中单位 |
| **星舰系** | 苍穹巡洋舰 (Cruiser) | **终极巨兽：** 移动缓慢的空中堡垒，自带护盾，可释放“大和主炮”秒杀单体。 | 压制一切常规部队 |

## 6. 基于 Phaser 3 的技术实现方案

使用 Phaser 3 开发 RTS 游戏，需要合理的架构规划：

### 架构划分

1. **场景管理 (Scenes)：**
* `PreloadScene`: 加载图像、Sprite Sheet、音频资源。
* `ArkScene` (方舟界面): 战役外的UI界面，用于剧情对话、兵种升级、消耗“科技核心”点天赋。
* `BattleScene` (主战场): 核心RTS循环场景。
* `UIScene`: 覆盖在战场上方的HUD层（小地图、资源面板、建造菜单）。


2. **核心模块实现：**
* **地图渲染：** 使用 Phaser 内置的 `Tilemaps`。绘制地形、不可通行区域和高地边缘。
* **寻路系统：** 强烈建议集成 **EasyStar.js**。在Tilemap加载后，将网格数据传给 EasyStar。当玩家右键点击时，计算出路径，并让单位的 Sprite 按路径点移动。
* **框选与交互：**
```javascript
// 伪代码示例：实现框选逻辑
this.input.on('pointerdown', function (pointer) {
    this.selectionBox.startPoint = { x: pointer.worldX, y: pointer.worldY };
}, this);

this.input.on('pointerup', function (pointer) {
    let rect = new Phaser.Geom.Rectangle(
        this.selectionBox.startPoint.x,
        this.selectionBox.startPoint.y,
        pointer.worldX - this.selectionBox.startPoint.x,
        pointer.worldY - this.selectionBox.startPoint.y
    );
    // 遍历所有友方单位，如果在矩形内则设为“选中状态”
    this.friendlyUnits.getChildren().forEach(unit => {
        if (Phaser.Geom.Rectangle.ContainsPoint(rect, unit.getCenter())) {
            unit.select();
        }
    });
}, this);

```


* **状态机 (State Machine)：** 为每个兵种编写简单的有限状态机（FSM）。状态包括：`IDLE` (待机), `MOVING` (移动), `ATTACKING` (攻击), `GATHERING` (采集)。
* **碰撞与索敌：** 使用 `Phaser.Physics.Arcade` 的重叠检测（Overlap）来画一个大圆作为单位的“警戒视野”。当敌方进入该圆圈时，触发攻击状态。



### 性能优化建议 (针对网页端)

RTS游戏后期可能有几百个单位，Phaser 3 的物理引擎可能会吃紧：

* **对象池 (Object Pooling)：** 子弹、光束、死亡特效和甚至基础采矿无人机，必须使用 Phaser 的 `Group` 对象池来复用，严禁频繁的 `destroy()` 和 `create()`。
* **降低寻路频率：** 小队移动时，只让“队长”进行A*寻路计算，其余单位跟随队长进行简单的向量移动（Boids 群体行为算法）。
* **简化碰撞：** 子弹不需要真实的物理碰撞，只需计算发射时的目标距离，使用定时器（Timer）或补间动画（Tween）到达目标即扣血，大幅降低物理引擎计算量。
